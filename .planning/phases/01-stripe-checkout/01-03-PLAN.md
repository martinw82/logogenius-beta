<task name="Create order lookup API route">
Create `src/app/api/orders/route.ts` with GET handler:

- Accepts `?stripeSessionId=cs_xxx` query parameter
- Queries Order by stripeSessionId using Prisma
- Returns order details: id, tier, status, customerEmail, amount, paymentStatus
- Returns 404 if not found (webhook may still be processing)
- Follows existing API patterns from `src/app/api/orders/[id]/route.ts`

Note: This is a separate route from `src/app/api/orders/[id]/route.ts` (which uses path params). The new route handles query-param-based lookup.

<task name="Create order success page">
Create `src/app/order/success/page.tsx`:

- Receives `session_id` from Stripe redirect URL query params (via `useSearchParams()`)
- Shows loading spinner while fetching order details
- Calls `GET /api/orders?stripeSessionId={session_id}` to find the order
- **Success state (order found, paymentStatus=paid):**
  - Success checkmark animation (use existing lucide-react Check icon)
  - "Payment Successful!" heading
  - Order details card: tier name, amount (formatted from cents), order ID
  - "What's Next" section:
    1. We're processing your order
    2. You'll receive an email with your dashboard link
    3. Review and approve your logo design
  - "Return to Home" button
- **Processing state (order not found yet — webhook delayed):**
  - "Processing your payment..." message
  - Auto-refresh every 3 seconds (poll until order appears)
  - Timeout after 30 seconds: show "Contact support" message
- **Error state:**
  - Error message with support contact info
  - "Return to Home" button

Uses existing component patterns: `src/components/ui/button.tsx`, `src/components/ui/card.tsx`, `src/hooks/use-toast.ts`.

<verify>Page renders at /order/success?session_id=xxx, shows order confirmation or processing state</verify>
<done>Order success page shows confirmation with order details after Stripe redirect</done>
</task>
